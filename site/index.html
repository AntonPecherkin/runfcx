Three commands. No API keys from anyone. No gas.

# first: a Hetzner Cloud API token, 2 minutes (how)
# (0) get a server (deletes itself after 12 h)
npx runfcx provision --ttl 12h
# (1) start a Snapchain read node, wait for sync
npx runfcx node
# (2) give the client its own app key, then use it
npx runfcx login --wallet
npx runfcx feed · cast · follow · like
# done? delete the server, billing stops
npx runfcx destroy
npx runfcx provision --ttl 12h npx runfcx node npx runfcx login --wallet

Measured on our mainnet runs

What we found running it

  • Half the disk

    Upstream needs2 TB

    runfcx needs1 TB

    Upstream keeps every download and a full archive until the end, about 1600 GB at the peak. runfcx unpacks as it downloads. Our node ended at 557 GB.

  • Survives a crash

    Upstreamweeks

    runfcxresumes

    If the restore stops halfway, upstream rebuilds the missing shards block by block (snapchain#1044). runfcx picks up where it left off.

  • No gas, no ETH

    Signatures2

    Gas$0

    Your wallet signs twice. No transaction.

Snags we hit, so you don't
  • Upstream's installer can quit before the node starts. runfcx starts it
  • The server's own firewall can block gossip. runfcx opens the port
  • A shard can quietly sync from block 1 for weeks. runfcx status warns you
  • Finding your account on a real node takes ~22 s. runfcx waits for it

What it costs

provision rents a Hetzner server and a 1 TB volume, and deletes both when the time you gave it runs out (8 hours by default, 12 in the quickstart). runfcx extend adds time. You pay Hetzner by the hour.
