Renting the server

runfcx rents the server for you on Hetzner, by the hour. You make one API token; npx runfcx provision does the rest.

What the node needs, on any provider
  • 4 vCPU, 16 GB RAM
  • 1000 GB disk. runfcx unpacks the snapshot one shard at a time and deletes chunks as it goes. Our run ended at 557 GB.
  • Ubuntu 24.04, billed by the hour

Hetzner · 2 minutes

  1. In Hetzner Cloud, create a new project just for this. A token controls its whole project.
  2. Security → API tokens → Generate, with Read & Write. Copy it.
  3. Save it where runfcx looks (or set HCLOUD_TOKEN instead): 
    mkdir -p ~/.config/fcx && pbpaste > ~/.config/fcx/hcloud-token && chmod 600 ~/.config/fcx/hcloud-token
  4. Run npx runfcx provision --ttl 12h

provision creates a ccx23 server (4 vCPU, 16 GB) in Falkenstein, a 1000 GB volume and a firewall that allows SSH from your IP only and UDP 3382 (gossip) from anywhere. It makes its own SSH key.

The server deletes itself when the time runs out: 12 hours here, 8 by default. Setup takes 5 to 6 hours. Need longer: npx runfcx extend 4h, or start with --keep. When you're done, npx runfcx destroy deletes the server and the volume, and billing stops.

Any other server

Any Ubuntu or Debian machine with the spec above works: a box at home, or a server from any cloud. Open SSH (22) from your IP and UDP 3382 from anywhere. Make the SSH key runfcx uses and put the public half in root's authorized_keys:

mkdir -p ~/.fcx && [ -f ~/.fcx/ssh_ed25519 ] || ssh-keygen -t ed25519 -N "" -C runfcx -f ~/.fcx/ssh_ed25519
cat ~/.fcx/ssh_ed25519.pub

Then:

npx runfcx provision --host root@YOUR_IP --data-dir /mnt/fcx

Example: Vultr

Our first two runs used Vultr. In its dashboard:

  1. Make the SSH key runfcx uses, and add the public half under Account → SSH Keys: 
    mkdir -p ~/.fcx && ssh-keygen -t ed25519 -N "" -C runfcx -f ~/.fcx/ssh_ed25519
cat ~/.fcx/ssh_ed25519.pub
  2. Network → Firewall: allow SSH (22) from your IP only, and UDP 3382 from anywhere. Nothing else.
  3. Storage → Block Storage: a bootable 1000 GB volume with Ubuntu 24.04.
  4. Deploy → Dedicated CPU → vx1-g-4c-16g, in the same location, with that volume, your key and your firewall. Turn off backups.
  5. Run the provision --host line above.

When you're done with your own server: run npx runfcx destroy --yes, then delete the server and its disk in your provider's console. A stopped server still bills.
